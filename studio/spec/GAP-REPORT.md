## Domain findings

### Widgets and on-stream graphics

Only a generic overlay-box layer (add/toggle/drag/resize, painted into the composited canvas) genuinely works; the entire user-created widget/browser-source system is absent, the brand/theme/QR/caption panels are local-state mockups, and the two real engine renderers (countdown, chat-on-stream) are never invoked by any UI.

### Video effects pipeline (colour filters / LUTs / virtual backgrounds / segmentation / beautify)

The video effects pipeline does not exist at all: there is zero WebGL/WebGL2/GLSL/MediaPipe code anywhere in web/src — the compositor is a Canvas2D programme mixer, and every documented effect survives only as unread settings fields plus a Settings modal wired to local useState.

### Audio

The engine layer has a credible mixer core (correct gain enum, per-source src-gain-dest graph, a real volumeMeter worklet at 24 Hz), but almost nothing above it is wired: the entire Audio settings panel is local useState over hardcoded fake device lists, no UI anywhere calls setGain/setMuted/setSolo, the whole music/SFX/player-service surface is absent, and the gUM constraints ignore the settings store that already persists them.

### Destinations and multistreaming

Only the RTMP plumbing is real — an in-memory destinations CRUD API plus a genuine ffmpeg tee fan-out to N enabled targets — while the entire destinations product surface (58-platform catalogue, OAuth and manual connect forms, per-platform validation and payloads, scheduling, limits) is absent, and the ChannelsModal the user actually sees is pure local useState wired to nothing.

### Sources, guests and media

Only the four local capture paths (camera, screen, local video file, image) genuinely reach the compositor; every one of AddSourceModal's 8 tiles is a no-op, and the host studio never joins a room at all, so no guest stream, approval flow or per-guest control exists on the host side.

### Studio side panels (tool rail + QR Codes + Captions per TOOLS-06; plus reality check on Sources/Chat/Graphics/Theme/Notes/AI)

Only the Sources panel (engine-wired) and the Graphics overlay list (store to compositor) do real work; the rail is 8 of 19 tabs with none of the slot/badge/deep-link behaviour, and QR, Captions, Theme, Chat, Notes and AI are local-useState mockups — Captions is additionally built as a speech-to-text panel the spec explicitly says does not exist.

### Shortcuts, settings and persistence

Shortcuts and Settings are shells: SettingsModal is 100% local useState with zero connection to settingsStore (which has no importers anywhere in the app), nothing persists, nothing reaches the engine, and only 3 of 44 spec'd key bindings match the spec.

### Layouts, scenes and the stage

The stage renders and scene switching with cross-fade genuinely works, but the layout system is a hand-rolled substitute sharing almost nothing with the spec's LayoutV2 model — the layout enum, per-layout option objects, tile shapes/radius/gravity and the Customize modal are absent or purely cosmetic, and scene reorder/duplicate/rename plus countdown-scene behaviour are unimplemented.

### Server API, events and persistence

The server implements roughly six of ~32 documented capabilities — destination CRUD, an ffmpeg RTMP fan-out, mesh signaling, room roster, studio chat and a stream-key stub — while auth, persistence, events/scheduling, users, recordings, files, analytics, clips, pairs and the entire binary room-manager protocol are absent, and every surface that does exist is unauthenticated and process-global.

### Sub-applications and third-party integrations (TOOLS-04, TOOLS-07)

Essentially none of this domain exists: neither web/package.json nor server/package.json contains hls.js, @mediapipe/tasks-vision, aws-sdk, ai/@ai-sdk, Stripe, Intercom, Canny, Segment, Amplitude, Datadog, Turnstile or gapi, and no source file references any of them; the trim editor, the 28-theme chat embed kit and the ~72-tool AI agent are absent entirely, with only an honest no-provider AI stub, a partial original chat-overlay canvas renderer and unused captured assets (MediaPipe .tflite/wasm in web/public/mediapipe, theme fonts in web/public/fonts) standing in — and no repo document declares any of it intentionally out of scope.
